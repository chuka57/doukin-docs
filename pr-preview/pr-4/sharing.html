今回の配信方法

GitHub Pagesで読む ↗

PublicリポジトリからHTMLを配信する方法。GitHub内で資料を更新し、同じURLから最新版を読めます。資料とソースは一般公開になります。

未設定の候補

URLで読む：認証付き配信 ↗

Workers Static Assets＋Cloudflare Accessを候補に。スマホから読みやすく、更新先を１つにできます。設定・支払情報・ログイン連携が必要です。

GitHubの通常ファイル画面ではHTMLはソース表示になります。Wikiも任意のCSS/JavaScriptを使うサイトの配信先にはなりません。HTML本体と共通assetsをセットで扱おう。

URLで共有する場合の構成案

無料の条件
静的配信は無料・リクエスト無制限。Accessは最初の50人まで無料という案内です。標準workers.devを保護できるので、資料用の独自ドメイン購入は必須にしない案。S19 S10 S52 S53
支払情報
Zero Trust Freeでも初期設定の支払情報入力が必要と公式に明記。無料プランでは課金されない案内と、支払情報不要は別です。S50
閲覧者の認証
開発メンバー個人のGitHubログインを候補に。組織・チームやメールの読取権限を求めるため、メール情報を一切渡さない方式ではありません。会社アカウントは使いません。S51
公開範囲
GitHubのリポジトリ権限は自動でサイトに引き継がれません。Accessの許可対象を別に設定し、実際に閲覧してよいメンバーと対応させます。
保護の確認
本番URLだけでなく、Version/Preview/Deployment URL等も対象。内容を置く前に保護し、未ログイン・非メンバー・失効済みで拒否されるか確認。S52 S53
資料とアプリのログインは、別々に検討します

開発者の資料閲覧に個人GitHubを使う案でも、アプリの参加者全員にGitHubを要求する意味ではありません。アプリの「個人メール以外を優先する」条件はそのままです。

GitHubの機能と、今回の使い分け

GitHub上での管理と、HTMLの配信を分けて考える
機能できること今回の注意点
通常PR比較資料をレビューし、履歴を残す。資料のマージと、技術採用の合意を区別。
Draft PR作業中として共有する。org privateのGitHub Freeでは使えない。Team/Enterprise Cloud等の条件を確認。現在の契約は未確認。S54
WikiMarkdown等の文書を整理する。private Wikiには対応プランが必要。公開範囲はrepoに従い、リンク限定やページ別ACLはない。S44
GitHub PagesHTMLサイトを配信する。private repoだからサイトもprivateとは限らない。組織サイトの非公開配信にはEnterprise Cloudの条件。S46

更新するときの、お約束

  1. 調査資料を更新する

    テーマ別原稿と、content/revisions.jsonの版・改訂日・短い変更要約・PR番号を更新し、HTMLを生成します。出典確認日は実際に再確認した場合だけ更新。採用結果・確定要件は転記しません。

  2. PRでレビューする

    料金・上限は公式情報を再確認。別モデルのレビューも補助にし、最後は根拠と実機検証で判断します。

  3. 入口を一定に保つ

    index.htmlとテーマのURLを維持し、Issueから該当ページへリンク。複数の場所に本文をコピーして手動更新しない方針です。

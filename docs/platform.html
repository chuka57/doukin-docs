03 / PLATFORM

部品の役割から、
組み合わせてみよう。

フロント、認証、API、DB。それぞれの役割をそろえると、サービスの違いを比べやすくなります。

Issue #4確認 2026-10-30 · JST
アプリをつくる４つの部品配信先を見くらべよう組み合わせの境目を確認しよう３人で保守するための、小さな約束
まずは、部品の役割をそろえよう。

同じサービスでも、画面を配る・APIを動かす・データを保存する、では条件が違います。ログイン後の小さなアプリなら、静的な画面＋必要なAPIから始める案を優先して比較します。

アプリをつくる４つの部品

React＋Vite案
画面をビルドして静的に配信。記録の取得はAPIや管理型DBを利用。公開検索やSSRが必須でない今回の候補です。
Next.js案
チームの経験があるなら比較対象。静的exportと、SSR／Server Actions等を動かす構成を分けて検討します。
Hono案
Workers上のAPIを整理する候補。招待・復旧・権限が自動で完成するわけではありません。

配信先を見くらべよう

GitHub Organizationのprivateリポジトリを維持する前提で比較
配信先今回の使い方気をつける条件
Workers Static Assets静的な画面を配信。必要なときだけWorkers API。静的配信と動的処理の枠を区別。Cloudflareは新規案件にWorkersを案内。S18 S19
Cloudflare Pages既存経験がある場合の代替。Pages FunctionsはWorkers枠。500ビルド/月とWorkers Builds 3,000分/月は別。S21 S22 S23
Firebase HostingF1の静的画面を配信。App Hostingとは別。Sparkの転送枠と上限到達時の停止を確認。S32 S34
Vercel Hobby現在の無料Git連携先には選ばない提案。Organizationのprivate repoをGit連携でデプロイ不可。個人・非商用、コミット作成者にも条件。S37 S38

組み合わせの境目を確認しよう

Next.jsをWorkersへ

Cloudflareの公式経路はOpenNext。Nodeと同じ実行環境だとは見なさず、使う機能と互換性をプレビューで確認します。S17

認証を入れ替えるとき

ClerkのIDはアプリの会員と関連付けが必要。独自認証を入れただけでは、SupabaseのRLSが自動でその本人を認識しません。信頼するトークンの設計が要ります。

３人で保守するための、小さな約束

  1. 個人アカウントで、必要な権限だけ

    開発・運営にも会社SSOや会社メールを使いません。共通ログインを避け、保守担当を複数人にする案です。管理席数や既存の無料枠消費を確認します。

  2. プレビューは、検証データへ

    本番の会員・体重を開発プレビューへつなぎません。OAuthの戻り先やパスキーのRP IDも環境ごとに確認します。

  3. サービスを選ぶ前に、小さく動かす

    ビルドが通るだけでなく、招待・権限・失効・復旧・DB復元まで通して比較。WorkersのCPUやDB読取回数は実測します。

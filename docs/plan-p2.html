個人メールを許容する場合

個人メールを使える場合の代替案。Supabase標準SMTPは、参加者向けの本番配信には使えません。メール配信サービスを含めて選びます。S29

部品と、つながり

画面とデータ
P1と同じ静的画面＋Supabase構成。認証の入口を個人メールへ変えます。
配信
SMTPの無料送信枠、送信ドメイン、DNS設定、認証メール用の運用を確認。Supabase側のレート制限もあるので、SMTPだけ大きければ十分ではありません。S29 S58
復旧
個人メールへアクセスできれば再ログインしやすい案。ただしメール変更・メール自体の紛失は別の本人確認が必要です。

利用者は、こう使う想定です

  1. 招待と個人メールを確認

    会社メールは使わず、参加資格を別途確認。メールを確認できたことだけで承認済みにしません。

  2. コードまたはリンクを受け取る

    OTPを入力する方法と、Magic Linkを開く方法を比較。再送間隔、期限、迷惑メール、スマホのブラウザ切替を実機で確認します。

  3. 記録と共有範囲を管理

    RLSで本人の記録と共有を制御。メールをタイムラインや公開プロフィールへ出さない設計です。

  4. メール変更・紛失・退会に対応

    通常の再ログイン以外に、本人確認後の変更手順と旧セッション失効を準備します。

うれしいところと、引き受けること

よいところ

参加者が個人メールを利用できれば、使い方と復旧経路を説明しやすい。独自パスワードの保守を減らす方向です。

開発・運用の負担

配信失敗・迷惑メール・再送・メール変更・送信ドメインを保守。メールを認証基盤で保有するため、ユーザーの優先条件との調整が必要です。

無料で使うための条件

Supabase Freeに加え、外部SMTPの配信枠と送信ドメイン費を確認します。標準SMTPはチームメール宛てのみ・２通/時。外部SMTP設定後もAuth側は初期30通/時の制限があり、調整と検証が必要です。S26 S29 S58

ここを確認しておこう

参加者全員をSupabaseの開発チームへ追加して、標準SMTP制限を回避する運用はしません。メール基盤の選定前に「完全無料」とは結論づけないでね。

初期構成は写真なしを基準にした比較。必要な費用・管理席・既存利用量は、採用時にも再確認します。サービス別の無料枠へ →

採用前に、小さく試すこと

  • 個人メール利用を許容し、会社メールを使わない前提で参加できる。
  • SMTP・ドメイン・送信認証・配信上限・Supabaseの制限を合計して費用と設定を確認。
  • 複数人が同時に登録しても、再送制限や迷惑メールで参加できなくならない。
  • OTPとリンクの期限・再利用・戻り先・メールアプリからのブラウザ切替を確認。
  • メールを失っても、本人再確認から元の履歴へ戻せる。会員失効とRLSも試す。

状態：すべて要検証。ここは試作の合格条件案で、実装済み・本番で確認済みの項目ではありません。

この案を選ぶか、相談するとき

メールを使わない候補が運営負担や制限で合わなかった場合に比較。実装前に個人メールの許容と、SMTPを含む支出を相談します。
